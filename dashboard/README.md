# 看板前端

在项目根目录运行 `python scripts/run_mock.py --web`，打开 `http://127.0.0.1:8765`。
使用标准库 HTTP 服务和原生 HTML/CSS/JavaScript，不依赖外部 CDN、Node 构建或开发板。

## 页面

- `/`：事件总数、成功与未成功记录、事件成功率、最近 5 条事件、待确认目标、流程说明和类别概览。
- `/events`：按类别、结果、原因和关键词组合筛选，每页 10/20/50 条。自动更新保留筛选和当前页；同一标签页内保存筛选条件。
- `/categories`：四类事件数量、占比及各类成功记录。无目标事件不计入四类占比。
- `/status`：待确认类别、事件接口连接状态、历史异常计数。未提供的机械臂和相机状态明确显示为“暂未提供”。

## 数据与刷新

保留 `GET /api/events` 原有字段：`events`、`summary`、`pending_cls`、`by_class`、`fallback`。
`POST /api/events` 继续供控制端写入事件，字段定义仍在 `shared/schemas.py`。
页面首屏由 Python 渲染，随后每 0.5 秒请求接口，局部更新内容，不重载整页；在接口正常的局域网环境下，为事件写入后 1 秒内可见留出轮询余量。
请求超时或失败时保留旧数据，显示失败提示和最后成功同步时间，自动重试，也可以点击“更新”。

统计口径：

- “事件总数”和“未成功事件”包含无目标、确认超时等记录，不等于垃圾数量。
- “事件成功率”是成功事件数除以全部事件数；没有记录时显示 `—`。
- 类别图统计带类别的成功及未成功事件；实际成功记录另列。
- 演示中的小数值时间戳显示为“时标”；Unix 秒或毫秒时间戳按浏览器本地时间显示。
- 模拟入口标记为“模拟演示”。普通事件服务只标记为“事件数据”，接口正常不代表硬件在线。

## 修改位置

- `server.py`：页面布局、首屏渲染和静态文件路由。
- `static/dashboard.css`：统一样式与响应式布局。
- `static/dashboard.js`：轮询、筛选、分页、状态与图表更新。
- `store.py`：事件存储及读取时的一致性快照。

外部字段在 HTML 和初始 JSON 中转义，浏览器动态表格同样转义。
当前没有视频流、启动/暂停或人工确认指令接口；这些能力需要与控制、视觉模块共同定义后再加入。

## 验证

`python -m unittest discover -s tests` 验证接口、统计、静态资源、首屏和转义。
联调时检查新增事件自动出现、筛选保持、待确认出现后清除，以及接口断开和恢复。
